# md-oretools 仕様書・開発ロードマップ

## 1. コンセプト

[FF14俺Tools](https://ffxiv.es.exdreams.net/) のように、遊戯王マスターデュエルをプレイする上で「自分が欲しい便利ツール」を1つのWebポータルに集約し、段階的に育てていく個人用Webサービス。

- **ブラウザ完結**: 専用ソフトのインストール不要、サーバーコストゼロ。
- **安全な自動化**: ゲームのプロセス・通信には一切触れず、ブラウザの画面共有（`getDisplayMedia`）経由の画面認識のみで完結させる。

---

## 2. 主要機能要件

### ① 手札確率シミュレータ

- デッキ枚数（40〜60枚）、初手枚数（先攻5枚 / 後攻6枚など）を指定可能。
- カードグループ（例: 1枚初動、2枚初動A、誘発、引きたくないカード等）を自由に定義し、枚数と条件（○枚以上 / ○枚以下 / ○枚ちょうど）のAND・OR組み合わせで初手確率を計算する。
- 多変量超幾何分布による厳密計算、および複雑な条件向けの高速モンテカルロシミュレーション（例: 10万回試行）に対応。
- よく使うデッキ構成のプリセット保存機能。

### ② 誘発カンペ（辞書＆リアルタイム連携）

- **辞書モード**: デッキタイプ（テーマ名）やカード名から検索し、手札誘発（灰流うらら、増殖するG、無限泡影／エフェクト・ヴェーラー、屋敷わらし、ニビル、墓穴の指名者、ドロール＆ロックバード等）の打ちどころを即座に表示。
- **自分用メモ編集**: 画面上から各テーマの対策メモやトリガーカードを自由に追記・編集・保存可能（JSONバックアップ対応）。
- **リアルタイム連携モード**: 戦績トラッカーの画面認識と連携し、相手デッキが類推された瞬間に該当テーマの誘発カンペを自動で表示する。

### ③ 画面認識・戦績トラッカー

- ブラウザの `getDisplayMedia` でマスターデュエルのウィンドウ映像を取得し、画面上の特定領域（ROI）を定期解析する。
- **自動トラック項目**:
  - **コイントス結果**（表 / 裏、先攻 / 後攻）
  - **選択デッキ（自分）**（事前に登録した自分のデッキをトラッカー上で選択・維持）
  - **相手デッキ（自動類推）**: 画面左上のカード詳細ウィンドウや発動演出からカード名をOCR（Tesseract.js）で読み取り、あいまい検索（Fuse.js）でカード名辞書と照合して相手テーマを類推する。
  - **勝敗**（VICTORY / DEFEAT の検知）
- **戦績の可視化**:
  - 先攻／後攻別勝率、使用デッキ別勝率、対面テーマ別勝率、コイントス確率などの集計・グラフ表示。
  - 自動認識が外れた場合でも、ワンクリックで手動補正・手動記録ができるハイブリッド設計にする。

## 3. 開発ロードマップ（ボトムアップ型）

### Phase 0: 足場づくり・品質基盤構築（進行中）

- リポジトリ初期化（`md-oretools` / Public リポジトリ ＋ Cloudflare Pages 配信前提）
- `AGENTS.md` / `docs/spec.md` / `docs/architecture.md` / `README.md` / `.gitignore` / `.gitattributes` / `.editorconfig` 整備
- Vite + React + TypeScript（厳格設定）+ Tailwind CSS + shadcn/ui セットアップ
- 品質ゲート基盤（`npm` + `Biome` + `Vitest` + `Zod` + `lefthook` + GitHub Actions CI + Dependabot）構築

### Phase 1: ポータル土台 ＋ 手札確率シミュレータ ＋ 誘発カンペ辞書

- 共通レイアウト（サイドバー／ナビゲーション、ダークモード基調のUI）
- **手札確率シミュレータ**の実装
- **誘発カンペ（辞書モード＆編集・保存機能）**の実装
  - 初期データとして代表的な環境テーマのテンプレートを用意
  - 各テーマに「自動類推用の代表カード名リスト」も持たせておく

### Phase 2: 戦績トラッカー（手動記録・集計基盤）＆ PWA 化

- 自分のデッキ登録機能
- 対戦ログ（日時、自分デッキ、相手デッキ、コイン、先攻/後攻、勝敗、メモ）の永続化（IndexedDB）
- 勝率・対面相性・コイントス統計ダッシュボードの作成
- データのJSONエクスポート／インポート機能（Zod スキーマ検証・バージョニング対応）
- PWA 化（`vite-plugin-pwa` による独立ウィンドウ起動・オフライン対応）

### Phase 3: 画面認識エンジン ＆ 誘発カンペ自動連携

- `getDisplayMedia` を使った画面キャプチャコンポーネントの実装
- ROI（認識エリア）の座標設定・プレビュー機能（プレイ環境の解像度に合わせて調整可能にする）
- コイントス／先攻後攻／勝敗の自動検知
- カード名エリアのOCR（Tesseract.js）＋あいまい検索（Fuse.js）による相手デッキ自動類推
- 相手デッキ判定イベントから「誘発カンペ」パネルへのリアルタイム自動切り替え連携

## 4. 今後の確認・調整メモ

- Phase 3 の画面認識実装時には、実際のプレイ解像度（例: 1920x1080）のマスターデュエルのスクリーンショット（コイン画面、カード詳細表示中、勝敗画面）を使ってROI座標とOCR精度をチューニングする。
